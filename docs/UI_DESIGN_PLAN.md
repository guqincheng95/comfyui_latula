# 拉图 UI 与互动设计计划

更新：2026-11-15。状态：已根据用户夜间像素港湾参考图细化第一阶段规格，尚未进行新首页实现、界面重构或第三方设计技能安装。当前第一阶段行为以 [第一阶段功能与交互规格](PHASE1_SPEC.md) 为准。

## 1. 已确定的要求

- 产品名为「拉图」，仓库名 comfyui_latula。
- APK 是连接 ComfyUI/其他 AI API 的便捷前端；模型推理与生成由连接的电脑或云端服务执行。
- 整体功能入口以道具式图标为核心，避免把所有功能都画成一个矩形框加几行文字。
- 第一阶段主页以用户本轮参考图为基准：像素港湾、工坊/齿轮、传送门/书本、图鉴/牌匾三个主区域，下方关于/更新/设置/退出。
- 三个主入口名称为装配工作流、进入工作流、历史任务；选定装配有边缘高亮，直接进入已装配工作流，历史用于图片/视频回看。
- 必须有点击与互动反馈；用户明确允许在计划书中先确定要求，后续逐步完善。
- 沿用 Vue 3 + Capacitor 工程，技术借鉴范围优先为 ComfyChair、ComfyUIMobileApp、Comfy Remote。

## 2. 视觉方向

第一阶段视觉方向已从通用立体道具探索收敛为参考图中的像素场景与游戏菜单：夜间港湾、像素人物、石板路、工坊、传送门、木质金属包边牌匾，以及蓝色月光与暖色灯光。保持有体积的方向性光照与局部环境动效；文字和触控区独立于背景实现，适应不同屏幕。造型细节仍可在试作中调整。

道具图标需统一视角、光源方向、材质与阴影、尺寸和视觉重量。图标自身可以有体积、层次和局部动作；整体界面仍保持清晰留白和稳定的位置关系。

首页不以等大文字卡片为主要表达。详细参数、错误说明、历史筛选和服务设置继续使用清楚易操作的表单/列表，不为了造型牺牲输入效率。道具入口保留简短中文名，不能仅靠颜色或抽象图形猜用途。

下表为更早的扩展道具提案，可能用于后续子页面；不是第一阶段新增的首页主入口，也不代表已承诺或实现对应业务功能：

| 可能的入口 | 道具隐喻示例 | 可以探索的局部动作 |
| --- | --- | --- |
| 图像相关应用 | 相片、画框、画笔 | 相片轻抬、画笔短划动 |
| 修复或增强应用 | 修复工具、放大镜 | 工具轻转、镜片局部高光变化 |
| 服装相关应用 | 衣架或叠放衣物 | 衣架轻摆、衣物局部切换 |
| 视频相关应用 | 打板或胶片 | 打板开合一次 |
| 我的素材/作品 | 文件夹或相册 | 文件夹开合、相片展开 |
| 连接服务 | 插头、连接线或服务器道具 | 连通后状态变化 |

## 3. 页面组织与状态

主页固定三个主入口，分别进入装配管理、当前工作流操作页和历史图鉴；运行中/失败任务归入历史区域的任务分组，底栏提供全局辅助入口。详细状态与行为以 PHASE1_SPEC.md 为准。

应用入口让人先看懂用途，再选择服务或应用；节点 ID、工作流内部结构等技术细节放在必要的配置区。详情页显示输入要求、可改参数、当前执行服务、提交入口和任务结果。

区分正常、按下、选中、不可用、上传中、已提交、排队、运行、成功、失败。尚未接通的服务和应用必须标明状态，不能以已可用的入口诱导提交。

动效不代表服务端执行进度。上传字节进度、平台返回的步骤与未知时长的等待分别展示；无可靠总进度时只显示当前阶段和耗时。

## 4. 互动动效规范草案

以下时长为试作初值，后续按真机效果调整：

| 场景 | 反馈方式 | 初始时长 |
| --- | --- | --- |
| 按下道具 | 轻微压下/缩放，阴影同步收紧 | 约 100–150ms |
| 松开或选中 | 轻回弹、局部动作或状态变化 | 约 180–260ms |
| 打开应用详情 | 保持入口与详情的空间关系，内容顺畅展开 | 约 220–320ms |
| 上传/排队/运行 | 不同状态使用有区别的反馈；上传进度来自真实字节 | 随任务状态 |
| 成功/失败 | 一次性完成反馈或明确失败提示，并给后续动作 | 约 200–350ms |
| 关闭或取消 | 立即反馈，保留已输入内容或明确恢复位置 | 约 160–240ms |

手机以点击/触摸反馈为主，悬停效果只作为桌面附加项。进入后台停止装饰动画，恢复页面后先同步实际任务状态。支持减少动态效果；列表滚动时不让所有道具持续循环播放。

道具上支持点击即可完成主要操作；长按、拖拽等如后续加入，需要可见的替代操作。触控热区建议至少 48 CSS px 并留有间隔，装饰轮廓小于热区时仍可方便点击。

## 5. 候选设计技能与项目

以下是调研候选，未自动安装或引入。设计技能帮助生成和审查设计，不能代替图标素材、动画资产或真实手机验证。

| 来源 | 能帮助本项目做什么 | 拟采用方式 | 当前状态/注意点 |
| --- | --- | --- | --- |
| Anthropic frontend-design | 确定鲜明的视觉方向，完善排版、配色、层次和互动反馈，避免通用模板外观 | 视觉稿阶段作为设计与审查参考；遵从本项目道具式入口要求 | 已读取官方技能文件与同目录许可证（Apache-2.0）；未安装 |
| UI UX Pro Max | 提供风格、颜色、字体和交互规范参考，包含 Vue 等技术栈指引 | 辅助建立设计变量和检查移动端体验；不照搬默认 SaaS 卡片方案 | 官方仓库标注 MIT；未安装或运行其 CLI |
| Motion for Vue | Vue 页面里的按压、回弹、布局变化、进入/退出动画 | 作为主要动效库候选；简单反馈优先 CSS，必要时再加入依赖 | 已核对官方文档；未加入 package.json |
| Microsoft Fluent Emoji | 早期立体物件造型参考 | 在本轮像素风格确定后降为次要造型参考，不作为首页默认素材 | 官方仓库标注 MIT；未复制素材，首页素材需符合像素场景风格 |
| Rive | 随按下、运行、完成等状态变化的局部互动道具 | 若少数关键道具需要更丰富的状态动画再评估 | 需制作适配资产并验证 WebView 性能；编辑器服务、运行时和素材授权分别核对 |
| Lottie Web | 播放已制作的短动画，用于空状态、完成反馈或局部图标 | 作为预制动画的备选，不与 Rive 默认同时全量引入 | 需准备动画文件并核对素材授权；播放器不会自动生成道具动画 |

推荐第一轮组合为：沿用 Vue/Capacitor + 统一道具素材 + CSS/Motion for Vue。仅在实际效果需要时选择 Rive 或 Lottie，不为美化一次性叠加所有动画运行时。普通关闭、返回、设置等小控件可以继续用统一线性图标。

另外已查询到 Figma、MagicPath 等设计插件，当前未安装或连接。若后续需要可编辑设计稿与协作，可再选用；当前计划不依赖外部账号，也不将 React 专用组件直接当成可用的 Vue 组件。

## 6. 交付顺序

1. 技术闭环：先验证选定应用的上传、提交、查询和结果，明确真实状态。
2. 视觉试作：对少量核心道具和同一个首页做风格对照，确定材质、光影和配色。
3. 设计系统：沉淀颜色、字号、间距、触控热区、阴影、图标尺寸及状态变量。
4. 动效样例：先完成一个真实道具的按下、回弹、打开和状态变化，真机确认后推广。
5. 页面整合：替换入口与公共组件，保持参数输入、任务恢复和结果操作稳定。
6. 验证：覆盖小屏/大屏、长名称、空状态、错误、弱网、前后台切换及减少动态效果。

## 7. 验收要点

- 首页第一眼能认出可操作的道具与用途，避免整页文字框。
- 点击反馈及时，页面跳转和动画不会阻塞主要操作或重复提交。
- 道具的材质、视角、光照和交互规则统一，动态与静态状态都能识别。
- 输入、进度、服务来源和错误状态表达准确，结果可预览与保存。
- 在真机 WebView 中检查流畅度、内存和后台行为；没有实测前不承诺帧率或功耗指标。
